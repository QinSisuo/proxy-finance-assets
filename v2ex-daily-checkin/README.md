# V2EX 每日登录奖励 · Loon 插件

在 iPhone 上安装一个插件订阅，让 Loon 每天读取自己账号的任务页，按页面提供的按钮领取铜币。默认每天本地时间 08:05 运行。每台设备可用同一订阅地址，登录授权在各自的设备上完成。

## 安装与更新

此版本使用 Loon 3.5.1（Build 983）起支持的脚本语法。

- **首次安装** — 用 iPhone 打开[在 Loon 中安装](https://www.nsloon.com/openloon/import?plugin=https%3A%2F%2Fraw.githubusercontent.com%2FQinSisuo%2Fproxy-finance-assets%2Fmain%2Fv2ex-daily-checkin%2FV2EX_Daily_Checkin.plugin)。也可以在 Loon 的「插件」中添加远程插件，长按复制[插件订阅地址](https://raw.githubusercontent.com/QinSisuo/proxy-finance-assets/main/v2ex-daily-checkin/V2EX_Daily_Checkin.plugin)。
- **已有本插件** — 进入「V2EX 每日登录奖励」详情，点右上角更新。确认能在插件的脚本列表看到「V2EX 检查登录」，以及结尾为 `V2EX_Daily_Checkin.js?v=20261125.2` 的脚本地址。保留一份启用的 V2EX 定时任务即可。
- 本插件的配置引用同仓库的 JavaScript 文件，由 Loon 下载。官方脚本规则接受文件路径或远程 URL，没有文档化的内嵌 JS 正文写法。手机上只需要安装上面的插件。[Loon 插件格式](https://nsloon.app/docs/Plugin/) · [脚本路径与定时规则](https://nsloon.app/docs/Script/script_v2/) · [导入链接格式](https://nsloon.app/docs/Scheme/)

## 用 Safari 授权

1. 保持 Loon 代理连接。在插件内打开「捕获登录状态」，「手动 Cookie」留空。旧设备已有可用凭据时，可先跳到下一节做只读测试。
2. 捕获需要在 Loon 内启用 HTTPS 解密（MitM），并安装和信任**自己这台设备上 Loon 的 CA 证书**。如刚安装描述文件，到 iOS「设置 → 通用 → 关于本机 → 证书信任设置」启用该证书的完全信任。本插件只声明 `www.v2ex.com`。关闭捕获只会停用响应脚本，插件的主机声明仍然存在。定时脚本自行发起 HTTPS 请求，已有凭据时不依赖 Safari 流量捕获。[Loon 的 MitM 配置](https://nsloon.app/en/docs/MitM/) · [Loon 关于证书与解密的说明](https://nsloon.app/en/privacy/)
3. 在这台 iPhone 的 **Safari** 登录自己的账号，从 V2EX 首页进入「领取今日的登录奖励」。已领取时也可以打开每日任务页，再刷新一次。等 Loon 提示保存成功后，关闭「捕获登录状态」。整个过程无需查看、复制或发送 Cookie。[V2EX 首页](https://www.v2ex.com/) · [每日任务页](https://www.v2ex.com/mission/daily)
4. 保存成功表示 Safari 返回了可识别的已登录任务页。下一步检查 Loon 自己能否使用这份凭据访问同一页面。

### 手动输入与旧版凭据

「手动 Cookie」供手上已有本人凭据的用户使用。填入单行值后，插件优先使用手动输入。想切回自动捕获时，先**清空手动值**，否则刚捕获的凭据不会成为本次使用的来源。手动值保存在插件设置里，请勿分享或同步含该值的配置、备份或截图。

自动捕获仅在任务页返回 HTTP 200、HTML 可识别为已领或提供合法领取动作时保存。脚本只取 `PB3_SESSION` 与 `A2` 这两个候选字段；这来自本项目以前的观察，V2EX 没有公开承诺登录所需的最小 Cookie 集。旧版记录也先过滤再使用。新版不删除其他脚本可能仍在使用的旧存储键。能明确区分的旧多账号记录可以沿用，若旧数据无法可靠拆分，请在此设备重新授权。脚本不会在通知、控制台或 GitHub 中输出 Cookie、整页 HTML 或一次性参数。

## 第一次测试与每天运行

1. **今天就能测登录**。在插件的脚本列表中手动运行「V2EX 检查登录」。它只读任务页，报告可领取、已领取、未登录或读取失败。若看到已领，今天可以验证登录和已领判断。
2. **测试实际领取**。在仍有奖励可领时，开启「每日自动领取」并手动运行「V2EX 每日奖励」。确认成功的通知是「签到成功，今日登录奖励已领取」。当天再运行，如果初次读到的页面已明确显示已领，通知是「今日已签到，登录奖励已领取」。
3. **核实铜币到账**。在 Safari 打开同一账号的账户余额，找类型为「每日登录奖励」且描述里奖励日期对应当天的记录。以该行的数额核对；「连续登录奖励」另列，午夜附近交易时间和奖励日期也可能不同。插件的成功通知依据任务页，到账金额以账单为准。[账户余额](https://www.v2ex.com/balance)
4. **启用定时**。在一台主力设备开启「每日自动领取」，将「运行时间」设为 `5 8 * * *`。其他设备仍可保留订阅。脚本会尽量避免同机同时执行，设备之间没有共享运行锁。
5. Cron 按 iPhone 本地时间执行。跨时区或夏令时变化后，本地 08:05 对应的 UTC 时间也会变化。站长曾说明奖励按 UTC 日切换，北京时间 08:00 进入新奖励日，脚本每次以网站实时任务状态为准。定时执行需要该任务启用、Loon 隧道运行、网络可用和 iOS 允许执行；可在 Loon 运行记录里查看实际触发时间。[站长关于奖励日期的说明](https://www.v2ex.com/t/67463) · [Loon Cron 格式](https://nsloon.app/docs/Script/script_v2/)

## 每次领取如何判断

已登录的 Safari 任务页上实际看到了导航到同站 `/mission/daily/redeem?once=…` 的控件。对这种导航，脚本使用 GET，直接使用当次页面的目标。它使用自己的客户端标识，在领取时将刚读取的任务页作为 Referer，按网站返回的会话更新处理可用的登录字段。每个请求限时 10 秒。登录跳转、验证码和限流均有独立处理。尚未确定 V2EX 对网页领取的具体频率限制。[每日任务页](https://www.v2ex.com/mission/daily)


| 当次读到的结果 | 脚本的动作 |
| --- | --- |
| 明确已领 | 直接结束。当天再次运行仍会读取网站。 |
| 任务页给出可识别的领取动作 | 正常模式按当前页面提供的地址提交一次，随后重新读取任务页。「V2EX 检查登录」到此结束。 |
| 提交后读到明确已领 | 报告今日已领。其他设备同时操作时，单靠网页状态无法判断由哪台设备领到。 |
| 提交响应丢失或结果不明 | 只读任务页核对。复查仍可领或无法识别时，通知此次结果，并提供回到 V2EX 手动处理的入口。 |
| 登录失效、验证码、明确拒绝或限流 | 停止自动处理。按通知回 V2EX 登录、完成网站要求的操作，或等限流解除。 |

每个账号的一次运行至多提交一次。不按本机日期标记「今天已经运行过」，不使用旧网页推断签到，也不根据余额总数或 HTTP 200 单独判成功。公开的 V2EX API 2.0 文档没有列出每日领奖接口，页面不再提供支持的动作时，以 Safari 当次显示的流程为准。[官方 API 列表](https://www.v2ex.com/help/api)

## 遇到问题

| 现象 | 在 iPhone 上怎么查 |
| --- | --- |
| Safari 能领，Loon 报登录失效 | 运行「V2EX 检查登录」复现。先确认手动值是否仍在覆盖自动凭据，再按授权步骤刷新一次任务页。若仍失效，保留通知中的阶段和 HTTP 状态即可。 |
| 刷新 Safari 没有保存通知 | 核对主机是 `www.v2ex.com`，页面是任务页，捕获开关、Loon 隧道和证书信任均已开启。在插件中确认脚本已下载，并检查是否有其他插件同时匹配这个页面。 |
| 领取后仍有按钮 | 到 Safari 打开同一账号的任务页及账户余额。还可领时可直接手动领取。单凭这个现象无法确定 Cookie 过期、网站改版或具体拦截原因。 |
| HTTP 403、429、验证码或网站要求手动操作 | 403 或验证提示按网页要求处理；429 表示请求受限，稍后再查看。不要连续点运行。 |
| 超时、远端断开或复查失败 | 在 Loon 中区分失败发生在读任务页、提交还是复查。提交过则先看账单，可稍后运行「V2EX 检查登录」重查。 |
| 到点未通知 | 查运行记录。没有记录时检查插件的启用状态、Cron、当天设备时区与隧道状态。有记录时打开对应脚本查看结果，同时检查 iOS 的通知权限。 |

反馈时只提供插件版本、阶段、状态码和通知文字。留在设备上的请求头、完整请求地址、登录凭据和账单截图均无需提供。

## 审查依据与测试清单

2026-11-25 完整检查了上一版配置、运行脚本、测试和说明。上一版在请求发出时即保存整个 Cookie，即使网页随后跳到登录页也可能覆盖已有记录；手动值会优先于新捕获的值。旧代码还允许特定提示触发第二次提交，并沿用 Loon 的自动跳转，难以从最终状态还原中间响应。这些是代码中可以确认的行为。更早的上游脚本还会读取持久化的旧任务页，曾在连接断开后误报已领。

用户提供的旧版账单能确认此前有过真实到账；最近几天能在 Safari 手动领取，说明手动流程在该账号可用。缺少当日失败时的分类响应，无法从这些证据确定最近连续失败的唯一原因。参考 Gist 实际调用 anyehttp 的远程脚本；它不是 V2EX 对页面结构的承诺。[参考 Gist](https://gist.githubusercontent.com/hughshen/3225051bf7eee12d7f5bb71fead2e688/raw/MyCheckIn.plugin) · [参考脚本](https://raw.githubusercontent.com/anyehttp/quantumult-x/main/task/v2ex.js)
