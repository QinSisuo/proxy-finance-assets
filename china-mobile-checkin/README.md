# 中国移动全国版 App「签到有礼」· Loon 候选插件

优先供用户的上海移动号码测试，不自动处理黑龙江号码。这里的“上海号码”是使用说明，不代表插件已经验证了号码归属地或活动资格。

## 当前交付状态

本插件引用 [Curtinp118 的 cmcc.js](https://github.com/curtinp118/Scripthub/blob/main/scripts/cmcc/cmcc.js)，源码标注支持 Loon / Surge / Quantumult X、v1.2.0、更新于 2026-05-31。已静态检查和模拟测试，**尚未用上海号码验证真实签到、领奖或流量到账，也未在 iPhone 上验证导入**。首次安装定时任务默认关闭。

已核对源码使用全国活动域名 `wx.10086.cn/qwhdhub/`，签到后根据返回的 `taskAwardChance` 领取第一个奖励机会。它不能保证奖励是流量，也没有自动激活流量券、核实流量余额或处理上海省版 App 的逻辑。

2026-10-25 未登录访问源码指定的活动页面，被官方跳转到 App 下载/打开中转页。因此单靠公开网页无法确认上海号码的当期奖励和资格，需要在本人全国版 App 中完成首次测试。

## iPhone 安装与上海号授权

1. 在 Loon 插件管理中添加上方 URL，启用插件，保持本机代理连接。插件仅声明 `wx.10086.cn` 为 MITM 主机，需要 Loon 的 HTTPS 解密和已信任证书正常工作。
2. 打开全国版“中国移动”App，**确认当前登录的是上海号码**，进入你平时使用的“签到有礼”。不用把 Cookie 或手机号发到聊天中。
3. 等待“中国移动 / Cookie 已更新”通知。原脚本只保存包含 `QWHD_SESSION_TOKEN` 的 Cookie。如果没有通知，不能认定授权成功；有可能实际页面使用了别的活动入口或登录状态未被捕获。
4. 立即关闭插件里的“获取当前号码登录状态”，再切换其他号码。上游脚本只有一个本机数据键 `CMCC_Cookie`，后续捕获会覆盖前一个号码；本插件不做两个号码的轮流签到。
5. 在 Loon 的脚本列表手动运行“移动签到与领奖”。首次保持“每天签到与领奖”关闭，先检查通知，再回中国移动 App 确认签到日历和奖品。
6. 如果当天签到和奖励结果都符合预期，再开启“每天签到与领奖”。默认设备本地时间每天 08:35，可在插件参数中修改。Cookie 过期后按第 2～4 步重新授权。

## 如何确认领到流量

- “签到成功”只说明签到接口返回成功。
- “签到+领奖成功”及奖品名称只说明领奖接口返回成功，可能得到话费券或其他奖励。
- 流量券通常还需到 App 的卡券或该活动的奖品页面查看使用条件并激活。本插件没有激活卡券的步骤。
- 最终应在 App 的流量余量/套餐资源或运营商到账通知中确认新增流量。尤其要核对日包、月包、定向流量以及失效时间；日包可以等到需要使用时再决定是否激活。

## 出错时需要提供的信息

只提供 Loon 通知文字和活动名称；如果提供截图，请遮住手机号。不发送 Cookie、登录请求、验证码或完整抓包。

如果没有 Cookie 通知，先确认当前是上海号码、捕获开关已开启、MITM 已生效及签到页面是否走 `wx.10086.cn/qwhdhub/`。若实际入口不同，需要核实页面后再适配，不能套用省版签到接口。

## 源码检查发现的限制

- 上游只支持单份本机会话，不会核对手机号或归属省份。
- 只处理签到响应返回的第一个奖励机会，不处理全部历史卡券。
- 上游 Loon 适配层使用 `resp.statusCode`，没有正确利用 Loon 的 `resp.status`，也没有据此统一判断 HTTP 错误；本插件没有把这一点标记为已解决。
- 领奖 Promise 没有接入最外层错误处理，领奖网络异常可能要等 Loon 的 60 秒脚本超时结束。无法仅凭无通知推断成功。
- 直接引用上游脚本，未来上游更新会影响行为。只在确认该号码实际结果后启用定时任务。
